Date Palm AI

Count date palms from aerial imagery with your trained YOLO26 models, for single images, for any of the 7,124 farms in your boundaries KML, or for areas you draw yourself.

Overview

Upload an image

Drop any aerial JPG or PNG, get the palm count and an annotated image. Page: /

Farm map

All farm polygons from your KML on a map. Select a farm (or draw an area), capture imagery from Google Earth Pro and get the count inside the polygon. Page: /farms

Google Earth link

The app drives Google Earth Pro on the same PC: it flies to the farm, saves the image and works out its exact coordinates by itself.

Boundaries KML→ Select farm / draw area→ Capture from Google Earth (saved)→ YOLO detects palms→ Count inside polygon→ Image + CSV

Key facts

  • Models: every *.pt in the project folder is selectable. Default: yolov26l-mixed-data-70epoch.pt. Multi-class models are filtered so only palm classes count.
  • Data: boundaries_20260921_115521 (3).kml holds 16 regions and 7,124 farms (about 51,850 ha). Farm codes start with a region prefix, for example TYM- for Tayma (361 farms).
  • Everything runs locally on your Windows PC. The only network use is the map background tiles (OpenStreetMap / Esri) and the Leaflet scripts on the farm map.
  • Counts are model estimates. They have not been checked against a hand count yet (see Status).

Quick start

Requirements

  • Windows 10 or 11, Python 3.12.
  • An NVIDIA GPU is used automatically when present (tested on a GTX 1650 Ti with 4 GB); otherwise the CPU is used.
  • For capturing: Google Earth Pro installed and running on the same PC.

Install (once)

cd D:\date-palm-yolo
python -m venv .venv
.venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118   # omit the index URL for CPU only
pip install -r requirements.txt
pip install pyautogui pywin32 shapely scipy                                         # farm map + Google Earth capture

Run

.venv\Scripts\python app.py

Then open http://127.0.0.1:8000. The model needs up to a minute to load; the header shows AI Model Ready when it's done. Always use this address: opening the HTML files directly can't reach the AI backend. To stop the server, close its window or press Ctrl+C.

start.bat exists but its startup problem was never fixed. Use the command above.

Import your farm boundaries (once, or when the KML changes)

.venv\Scripts\python tools\import_kml.py "boundaries_20260921_115521 (3).kml"

This reads every region and farm and writes data/farms.json. Add --prefix TYM to keep only one code prefix.

Upload an image

  1. Open /, then drop a JPG/PNG on the upload box (or click to browse).
  2. Optional: choose a different Model in the header, or open Advanced Settings to change the confidence (default 0.15) and the processing mode.
  3. Press Analyze Image. You get the palm count, the average detection confidence, the image size, and the original next to the annotated image (each palm is a red dot).
  4. Use Download Result for the annotated image or Download Report for a text summary.

Processing modes: Automatic (recommended) measures palm size in your image and tiles it so palms appear about 24 px wide to the model; Single pass squeezes the whole image to 640 px (only sensible for small crops); Fixed tiles uses 640 px windows at full resolution. Limits: JPG/PNG, 100 MB, 250 megapixels.

Open /farms. The map shows all regions (dashed outlines) and farms (polygons). Colours:

The side panel

  • Find a farm: type a code such as TYM-00798 and press Go.
  • Layers: show or hide a region, zoom to it, or Select all farms in it.
  • Selection: the selected polygons, the Imagery options, and the Count palms button.
  • Custom area: draw your own polygon.
  • Result: count, density, labelled image, imagery date and an Open in Google Earth button.
  • Google Earth Pro: link status and the Link Google Earth button.
  • Totals: palms counted so far, and Export CSV.

The background map can be switched (top right) between street map, Esri satellite and none. These are for orientation only; counting uses the images captured from Google Earth.

Count a farm, step by step

  1. Start the app and open http://127.0.0.1:8000/farms.
  2. Start Google Earth Pro and leave its window open and in front.
  3. In the app press Link Google Earth and wait for the green “linked” dot. The app answers Earth's confirmation prompts for you.
  4. Select the farm: click its polygon, or type its code. Several farms can be selected (click each, or use Select all farms for a region).
  5. Choose Imagery → Capture new from Google Earth (and save it). Leave Imagery date on Newest well-lit date.
  6. Press Count palms. The app tells you how many Earth captures are needed and the time, then asks you to confirm.
  7. Don't touch the mouse or keyboard while it captures: the app clicks in Earth for you. Expect about 1–3 minutes per farm.
  8. When it finishes, the farm turns green on the map and the panel shows the count and the image. The capture is saved for later.
Counting again later without Google Earth: choose Use a saved capture (no Earth needed). If the farm has several saved captures you pick which one. This takes a few seconds per farm.

Draw a custom area

  1. Press Draw an area in the Custom area panel and click the corners on the map. Click the first point to finish.
  2. Give it a name (optional) and press Save & select. It gets a code such as AREA-0001.
  3. Count it exactly like a farm. Palms are counted inside your polygon only. Areas are limited to 25 km².

Areas are stored in data/areas.json; the Delete area button removes one. Export CSV in that panel lists area counts.

Working with Google Earth

The app and Earth are connected through a KML network link: Earth regularly asks the app for farm polygons and for a “camera” position. The app uses the camera to make Earth fly to a place. There is no API that returns Earth's imagery, so the app saves it by driving Earth's own Save Image command with simulated mouse and keyboard.

What the app sets up in Earth automatically

  • Earth window maximised, resolution 4K (3840×2160).
  • Sun, Atmosphere, Grid, Overview map and Scale legend switched off; Title, Legend, Scale and Compass overlays switched off.
  • The farm polygons are hidden from Earth during a capture so they aren't saved into the picture.
  • A well-lit imagery date is chosen (see Imagery options).
  • Earth's “Crash Detected” and “only open files you trust” prompts are answered for you.

Linking

Link Google Earth (or POST /earth/open-link) loads Date Palm AI.kml into Earth. You must link again after restarting the server. Open in Google Earth on a farm makes Earth fly to it.

Rules while capturing

  • Earth Pro must be running, maximised and not covered by other windows.
  • Nobody should use the mouse or keyboard. Moving the mouse into a screen corner aborts the automation (pyautogui safety).
  • Earth is slow to start and has crashed once during testing; the app handles the restart dialogs.

Why dates matter

The newest Tayma imagery (late 2025 to early 2026) is nearly black in the palm groves, so crowns can't be seen. On the same farm, a clear date gave 375 palms and the dark newest imagery gave about 20. Brightening the dark image only recovered about 12% of the palms, because the detail isn't in the image. The date picker therefore measures brightness and contrast of each date and chooses the newest one that is well lit. It takes about 2 minutes once per capture job.

The app checks the brightness of every polygon's imagery. “Dark” or “very dark” results show a warning on the page. Dark imagery is brightened automatically before detection, and dark previews are brightened on the map.

Earth's time slider fades out when the mouse isn't over it. It is still there: hover the top-left of Earth's map, or use View → Historical Imagery.

Results & exports

  • On the page: count, palms per hectare, average confidence, imagery date, the labelled image (polygon outlined, palms dotted, code and count in the banner) and a clean version. Click the image for a full-size viewer.
  • Files: results/farms/images/<code>.jpg (latest labelled image), raw/ (clean), points/ (palm coordinates), summary.json.
  • History: every run is kept in results/farms/runs/<code>/<time>/ with capture.jpg, detection.jpg and result.json.
  • CSV: Export CSV lists code, region, type, status, count, area, palms/ha, confidence, imagery source and date, model and time, with a total row. Use /api/farms/export.csv?region=Tayma for one region and ?kind=area for custom areas.
  • Google Earth: /earth/farm/<code>.kml gives a farm's polygon plus every detected palm as a point, to check over Earth's own imagery.

Region grid capture written, not finished

For counting thousands of farms, capturing one farm at a time is too slow (one Earth capture takes about 30–100 s). The region grid capture covers an area with a grid of overlapping Earth views instead, so one view serves many farms.

The run (code in palmai/regions.py) prepares Earth, captures every cell, detects palms in each cell for the outside-farm count (palms cut by a cell border are dropped when a neighbouring cell sees them whole; duplicates within 1.5 m are merged), then counts every farm by cropping it out of the cells and saves that crop under the farm's code. It can be cancelled and resumed. Endpoints: POST /api/farms/regions/estimate, /regions/run, GET /regions/result.

Not finished: there is no button for it in the page yet, it has not been run on a real region, and a map layer stitched from the cells (a GeoTIFF / tiles) is not built. Which camera height is best has not been measured (only 600 m at 8K was verified: 375 palms on a dense farm).

Detection pipeline

  1. Palm size sets the scale. The models were trained at 640 px and see best when a palm is about 24 px wide. In automatic mode the app probes the image, measures the median palm width and picks a tiling window so palms appear about 24 px (PALM_TARGET_PX). For farm crops, the expected palm size (7 m) is used when too few palms are found to measure.
  2. Tiling. The image is cut into overlapping windows, each run through the model, boxes are shifted back to image coordinates and duplicates across tiles are removed (NMS plus a check that drops palms cut by one tile's border when the neighbour sees them whole).
  3. Palm classes only. Models trained with buildings, roads, fields and trees are filtered to their palm classes. Models with two palm classes (Date-Palm and Palm tree) are de-duplicated so one tree counts once.
  4. Dark imagery. If the polygon's brightness is low, a gamma lift is applied to the image before detection (and to the images shown).
  5. Inside the polygon. Each palm is the centre of its box; only centres inside the farm/area polygon are counted.
  6. Output. Dots are drawn at the palm centres. The average confidence is the mean confidence of the final detections (not model accuracy).

Defaults: confidence 0.15, up to 20,000 detections per image. If another program (for example Google Earth) takes the GPU memory, inference falls back to the CPU automatically.

How a capture works

  1. The app sets the camera (served to Earth in /earth/camera.kml) to the polygon's centre, top-down, at 600 m. Earth flies there.
  2. Four small magenta markers appear in Earth's view at known coordinates, 78% of the way to each corner.
  3. The app waits until the view stops changing (flight finished, tiles loaded).
  4. It clicks Earth's Save Image toolbar, picks the resolution, types the file name and waits for the file.
  5. It finds the markers in the saved image. Their pixel positions give the exact ground area the image covers (linear fit; the marker residual is checked), then the markers are painted out.
  6. Polygons bigger than one view use several captures that are stitched into one crop around the polygon (with a margin of 8% or at least 12 m). The crop is saved for the farm.

Extending the project

Add a model

Copy the .pt file into the project folder. It appears in the model dropdown immediately. It needs a class whose name contains “palm”; otherwise the app reports an error instead of guessing.

Add a new imagery source

Counting needs only a georeferenced image: a picture plus its bounds (west, south, east, north). palmai/imagery.py turns a source into Capture objects; FarmService.analyze in farms.py stitches them, counts and saves. To add a source (for example a licensed imagery provider or a drone GeoTIFF), produce Capture objects for the polygon and call analyze with caps_override, exactly as the region run does. Saved captures use the same format (data/saved/<code>/*.json with bounds).

Change what is detected

Palm class selection is in PalmDetector._get_model (classes containing “palm”). Scale and tiling are in detector.py (_auto_window, _detect_tiled, _merge).

Conventions

  • Coordinates are WGS84 (lon, lat). Pixel ↔ coordinate conversion is in geo.GeoImage.
  • Long operations run as background jobs (JobManager), one at a time, because the GPU and Google Earth are shared.
  • The Earth automation depends on screen positions (a maximised Earth window at 1920×1080). Different screen sizes or Earth layouts need the offsets in earth_capture.py adjusted.

Limitations

  • Accuracy is unverified. No farm has been hand-counted. Counts are estimates and move by about ±15% with the confidence slider. Young palms in sparse plots and palms in deep shadow are missed most often.
  • Imagery dates are Google's. The newest Tayma imagery is too dark for counting; the app uses the newest well-lit date and records it.
  • Speed. An Earth capture takes 30–100 s, so counting thousands of farms needs the region grid capture and overnight runs.
  • Fragile automation. Capturing relies on Earth Pro's window layout on a 1920×1080 screen and on simulated input. Earth Pro desktop is scheduled to be discontinued (June 2027).
  • Windows only for capturing; the upload page and counting from saved captures work wherever Python runs.
Imagery licensing. Imagery saved from Google Earth Pro is subject to Google's Earth terms (generally personal and non-commercial use with attribution). Bulk downloading of Google's tiles outside Earth Pro is not supported by this project. If the counts are for company or organisation use, check the terms or ask Google for permission. Licensed providers (for example Esri, Planet, Maxar, Airbus) or your own drone imagery can be used as another imagery source (see Extending).
